# Решения

## 006 — Уведомления через события Codex и общий конфиг доставки

Принято 23.10.2026 по прямому поручению пользователя. Локальный Python-хук
использует Stop/UserPromptSubmit, PermissionRequest и Pre/PostToolUse; сетевые
запросы и ожидание отделены от быстрого вызова хука. Доверие остаётся в /hooks.
Состояние на session_id изолировано и блокируется между параллельными событиями.
Конфиг ~/.codex/notify.env имеет приоритет, иначе читается ~/.claude/notify.env:
существующий топик не дублируется. Shell-конфиг читается как литералы, не исполняется.
Неизвестные фоновые shell-вызовы ограничивают задержку 15 минутами; известные
слушатели исключены. Для MCP-elicitation, подтверждения плана и /loop нет прямого
переноса события; ограничения и нестабильность rollout/index описаны в README.
Изменение установщика не означает применения глобальных настроек текущей машины.

## 002 — Дополнительная строка средствами tmux

Принято 14.10.2026. Штатная строка Codex выбирает готовые поля; произвольный скрипт для неё не документирован. Патч или форк Codex отвергнут: их нужно сопровождать после каждого обновления. Собственная строка tmux обновляется независимо и сохраняет официальный CLI. Отдельный сервер tmux не меняет пользовательские окна и настройки.

## 003 — Номер сессии из события, без догадки по последнему транскрипту

Принято 14.10.2026. Глобальный хук связывает уникальный запуск с `session_id` и `cwd`; CLI работает с `--no-daemon`, чтобы получать своё окружение. Последний транскрипт той же папки отвергнут: две сессии смешались бы. Пока хук не доверен, состояние сессии неизвестно. Доверие оставлено штатному `/hooks`.

## 004 — Сторож проверяет совместимость перед исправлением

Принято 14.10.2026. CLI выбирается стабильным путём `~/.local/bin/codex`; проверяются новые версии бинарника, конфиги восстанавливаются после обновления плагина. Отключение sandbox и закрепление старой версии отвергнуты. Перезапуск общего сервера отвергнут: он прерывает работу других сессий.

## 005 — Автоинициализация нового cx только по Work Worker opt-in

Реализовано2026-10-15 по прямому разрешению пользователя, полученному в work-worker
после предложения изменить эту обвязку. Новый пустой native запуск запрашивает
scoped readonly work-worker startup-context (timeout1.5s). Только version1/enabled=true
и соответствующий selected directory допускают фиксированный startup prompt с
ответом WW_SESSION_READY. Query не передаёт инструкции, команду/prompt из его JSON
не принимаем. Native trusted hooks дают ID; журнал/identity launcher не выдумывает.
Пользовательский prompt, resume/fork/picker, config/profile overrides, remote/worktree
и unknown CLI args сохраняются. Missing/invalid/timeout query — обычный запуск.
Есть один короткий service turn, не zero-cost hook; global hook не ускоряет native
SessionStart. Другие проекты не opt-in автоматически.
Live выявил замену WORK_WORKER_HOME вложенным shell из zshenv. Переменная включена
в существующий whitelist private launch metadata; launch.py восстанавливает и value,
и отсутствие после tmux shell. Другие env keys/родной --no-daemon режим сохранены.
Установлены только2 scripts с private backup, hooks/trust/shell/LaunchAgent не тронуты.
TDD/28 Python tests и реальная empty cx→trusted hook→open participant→mail read/reply/
processed выполнены; QA проект/broker изолированы после исправления и штатно закрыты.


## 007 — Возвращаться в живой cx через штатный tmux attach

Принято пользователем и реализовано23.10.2026 из сессии Work Worker по прямому
поручению исправить повторяющуюся блокировку, установить, commit/push и затем
остановить один конкретный старый запуск. Run прежде всегда создавал новый
server, даже при живом detached Codex того же разговора.
Решение: plain resume UUID ищет exact hook session ID в private run metadata и
проверяет живую pane с точной launch.py command. Bare resume предлагает живые
запуски текущей папки;0/Enter сохраняет native picker. Перед attach повторно
проверяются identity и attached state; другой клиент/неоднозначность дают отказ
без force detach. Dead/finished/corrupt/symlink metadata не кандидаты. Overrides,
fork и новые запуски сохраняют прежнюю семантику; inherited env при attach остаётся
у существующего процесса. tmux quoting нормализуется без исполнения команды.
Альтернативы: убивать Codex при закрытии окна теряет фоновые задачи; удалять
writer lock нарушает exclusivity; подменять штатный native picker сложно и
связывает обвязку с внутренностями CLI. Locks/shared server/hooks не меняются.
Последствия: два простых resume режима предотвращают лишний запуск; native picker
и нестандартные resume options остаются вне автоматического reattach.
