# Браузер и обновления

14.10.2026 на macOS 13.7.8 браузерный MCP использовал встроенный CLI ChatGPT 0.159.0-alpha.12.1. Его sandbox падал с `unbound variable: TIOCSTI`. Установленный отдельно Codex 0.162.1 проходил ту же проверку.

Исправление: `CODEX_CLI_PATH` у `mcp_servers.node_repl.env` в глобальном конфиге и у `cua_repl.env` в кэше плагина `unified-computer-use` указывает на `~/.local/bin/codex`. Кэш плагина может быть переписан обновлением, поэтому исходники сторожа живут вне него.

Сторож запускается перед терминальным Codex, при изменениях конфигурации и каждые 30 секунд. Новый бинарник сначала проверяется командой `codex sandbox /usr/bin/true`; результат кешируется по реальному пути, inode, размеру, времени изменения и версии ОС. При отказе настройки не меняются, причина пишется в `state/status.json` и `events.jsonl`. Файлы меняются атомарно, с проверкой параллельной записи и резервной копией. Меняется только выбранный путь CLI; sandbox и права не ослабляются.

```sh
codex-browser-guard
cat ~/.local/share/codex-browser-guard/state/status.json
launchctl print gui/$(id -u)/com.dima.codex-browser-guard
```

Уже подключённый MCP удерживает окружение в памяти: после обновления может понадобиться переподключение. Фоновая проверка чинит файл, но не перезапускает чужие сессии. Прохождение sandbox — проверка CLI, не доказательство связи с браузерным расширением. Живой Chrome отдельно проверен переходом по странице и снимком экрана. Нативный помощник управления приложениями требует macOS 14.4 и на macOS 13 не запускается; браузерное расширение Chrome работает отдельно.

Сторож также восстанавливает прямой запуск cua_repl без оболочки, которая подставляет пустой идентификатор desktop host, и без preload `require-browser-access.mjs`. У нативного `node_repl` список аргументов может быть пустым: это полноценный исполняемый файл, ему не нужен путь к JS-скрипту. Запуск `node` без скрипта по-прежнему считается неподдерживаемым.

11.11.2026 исправлен отказ `Unsupported cua_repl launcher` для такого нативного запуска. Восстановлены две конфигурации; повторный запуск ничего не меняет. В текущей сессии живая проверка cua_repl продолжила возвращать `The browser access host is unavailable`, а node_repl ссылался на уже удалённую старую версию browser-service. Это устаревшие настройки запущенных MCP: исправление файлов не заменяет их окружение. Сброс JS также не помог; связь с Chrome после переподключения ещё требует проверки.

Сторож защищает обнаруженные форматы запуска и путь CLI, но не гарантирует совместимость неизвестных будущих версий плагина. Неизвестная структура конфигурации приводит к отказу с причиной.
